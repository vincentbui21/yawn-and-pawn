- **Fixing flaky tests at the root found a real bug.** The #61 investigation showed that `SetAlarmEnabled`/`DeleteAlarm` could leave an alarm off or deleted with no system-alarm change and no event, if the caller was cancelled between the two writes. Fixed with `NonCancellable`, with tests that failed before the fix.

## Tests that depended on time or threads
- **#45** (`7535d6cb`): `withScreen`'s snapshot write was applied only by chance before a paused test clock advanced, so the "I'm up" pulse tests captured the wrong screen. It now calls `Snapshot.sendApplyNotifications`.
- **#60** (`b933283f`): `MainActivityTest` used the real wall clock, so between about 23:00 and 07:00 its 7:00 alarm fell inside 4.6's 8-hour lock and the test timed out (main CI at 04:29 UTC). It now boots `PinnedClockApp`. `SnoozeConfirmSheetTest`'s v1 compose rule recomposed on a `Dispatchers.Default` worker (`CalledFromWrongThreadException`).
- **#61** (`c11cc11b`): all 86 compose test classes moved to the junit4.v2 rules (StandardTestDispatcher), the waits were fixed for effects that now start only when the rule idles, and the production cancellation bug above was fixed.
- **Also:** CI time limits and a per-test watchdog (in #47), so a hung test fails by name instead of using up the 75-minute job.
